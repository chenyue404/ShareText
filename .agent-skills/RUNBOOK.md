# 执行手册（给你直接照着用）

## 一轮标准流程

1. 启动主助手

- 读取：`main-orchestrator/SKILL.md`
- 产出：本轮目标、每个子助手负责什么、通过标准。

2. 并行启动 6 个子助手

- A/B/C/D/E/F 各读自己的 `SKILL.md`。
- 每个子助手只能改自己负责的地方。

3. 收集结果

- 6 个子助手都按模板回报。
- 主助手统一判断“通过/不通过”。

4. 决定下一步

- 通过：进入下一轮。
- 不通过：退回对应子助手继续修。

## 主助手启动提示词（可直接复制）

```text
你是总负责人。请严格按 .agent-skills/main-orchestrator/SKILL.md 执行。
项目目标：在核心功能不变前提下，完成大版本升级。
先输出：
1. 本轮目标和范围
2. 每个子助手负责什么
3. 本轮通过标准
先不要改代码，先发任务卡。
```

## 子助手启动提示词（可直接复制）

```text
你是子助手 X。请严格按 .agent-skills/subagent-x-*/SKILL.md 执行。
只做你负责的部分，不要跨边界改动。
输出必须使用文档里的固定模板。
如果发现接口需要改，先上报总负责人，不要自行改接口。
```

## 第一轮建议分工

- A：现状检查和回归清单
- B：服务端逻辑
- C：安卓宿主和生命周期
- D：网页文件和前端行为
- E：构建和依赖
- F：上线风险和回滚计划
